# 基于 OCR 的食品外包装文字识别检测系统 —— 模型基础评估报告

## 1. 评测目的与背景

本系统面向食品外包装文字识别检测场景，共集成 **5 类模型**，需要分别验证其基础能力：

| 模型 | 定位 | 说明 |
| --- | --- | --- |
| 默认 OCR（官方 PP-OCRv4） | 基线 | 官方预训练，检测 + 识别 + 方向分类完整流程 |
| OCR 微调模型 | 微调 rec | 用食品标签数据微调识别部分，替换官方 rec |
| DB 文本检测 | 检测专用 | 只框出文字区域，不识别内容 |
| CRNN 文字识别 | 识别专用 | 只识别文字，不做检测 |
| 自定义微调模型 | 扩展 | 加载用户自己微调出的推理模型 |

评测目的：**(1)** 以官方模型为基线，验证微调后识别精度是否有提升；**(2)** 分别验证 DB 检测与 CRNN 识别两种单一算法能否正常工作；**(3)** 为后续选型与部署提供依据。

## 4. 评测指标与方法

### 4.1 识别模型指标（rec）

- **字符准确率（Char Accuracy）**：`1 − 编辑距离 / 最长字符串长度`，逐行求平均。衡量单字识别正确率。
- **整行准确率（Line Accuracy）**：预测文本与真值完全一致的行数占比。衡量整行识别正确率。

> 编辑距离（Levenshtein）：把预测文本改成真值所需的最少增/删/改字符数，越小越准。

### 4.2 检测模型指标（DB）

- **检测数量**：对单张图检测出的文字区域个数，与人工目测文字块数量对比，判断是否漏检/多检。
- **可视化验证**：将检测框绘制到原图上（系统「检测演示」页 `DB 文本检测` 模式自动生成 `*_det.jpg`），人工确认框是否贴合文字。

## 三、指标怎么来（实操步骤）

### 1) 识别模型指标（自动生成）

```bash
# 仅官方模型（拿基线）
python model_train/evaluate_rec.py --data ./data/rec_gt_val.txt

# 官方 vs 微调对比（微调模型需先导出 inference 目录）
python model_train/evaluate_rec.py --data ./data/rec_gt_val.txt \
    --model ./output/rec_ppocr_v4/inference
```

脚本会自动输出：
- `evaluate_rec_report.md`（可直接粘贴进报告第 5.1 节）
- `evaluate_rec_report.json`（原始指标）

### 2) DB 检测 / CRNN 识别（系统页面演示）

1. 到「系统设置」→ 把识别模型切到「DB 文本检测」，上传图片 → 得到检测框数量 + 可视化图。
2. 再切到「CRNN 文字识别」，上传同一张图 → 得到识别文本 + 置信度。
3. 截图填入第 5.2 / 5.3 节。

### 3) 微调模型导出（如果还没有 inference 目录）

```bash
# 用 PaddleOCR 自带的导出工具，把训练好的 latest.pdparams 导出为推理模型
python model_train/PaddleOCR/tools/export_model.py \
    -c model_train/ch_PP-OCRv4_rec_finetune.yml \
    -o Global.pretrained_model=./output/rec_ppocr_v4/best_accuracy \
       Global.save_inference_dir=./output/rec_ppocr_v4/inference
```

导出后 `inference/` 目录里会生成 `inference.pdmodel` 和 `inference.pdiparams`，即可在系统里加载。

## 四、写作常见坑（避开就够用）

1. **只贴截图不写数字** → 至少给每个模型一个量化指标。
2. **指标不解释** → 每个指标后加一句「它衡量什么」。
3. **结论和结果矛盾** → 微调没提升就如实写「持平，需补数据」，并给出原因，反而更像真做了实验。
4. **不写评测环境** → 软硬件版本必须写，这是评估报告的基本盘。
5. **数据量不写** → 明确写「共 N 条」，否则指标没有说服力。
